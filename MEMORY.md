## Decisions

- [05-28-2026] decision: All test files live in project-root `tests/` (e.g. `tests/gown-sizes.test.ts`). Do not colocate `*.test.ts` under `src/`.

- [06-08-2026] decision: Lightbox dialog preloads non-active carousel slides via loading="eager" to avoid the blur-placeholder flash when swiping; the hero (ImageViewer) stays lazy so visitors who don't swipe the inline carousel don't download unused photos. - [06-15-2026] decision: Navbar/chrome auth reads use supabase.auth.getClaims() (local JWT verify, no Auth-server round-trip when asymmetric JWT signing keys are enabled) via getCurrentUser — NOT getUser(), whose per-render network call caused the links to pop in after a visible delay. getUser() stays for security boundaries only (src/proxy.ts /dashboard guard, RLS). Requires asymmetric (ECC/RSA) signing keys in Supabase → Settings → JWT Keys; documented in docs/auth-setup.md §7.

- [07-02-2026] decision: Browse variant filters (size/price/availability) target an aliased `matched_sizes:listing_sizes!inner` embed — a listing matches when one available variant satisfies all of them at once (not the "lowest price" rule, which PostgREST can't express without an RPC); display sizes ride the separate `sizes:listing_sizes(*)` embed. Supabase select strings with embeds are typed `: string` to avoid TS2589 literal-parse blowup.

- [07-03-2026] decision: GownCard shows listingPriceSummary — set_only shows the set total (bundle_price); individual/either show `$425` / `$425 each` / `From $400`. The bundle note ("Complete set only" / "All for $X") is NOT rendered on cards, keeping every card a single line; the notes live only on the detail page. (listingVariantPriceSummary was briefly added for cards, then removed once set_only reverted to showing the total.)

- [07-03-2026] decision: Set-only listings store no seller-entered per-size price. The form hides the per-size price inputs when "sell as set only" is checked (ListingSizeRow `showPrice`; unchecking clears row prices so switching to individual forces re-entry), and the server (variantRowsPayload in sell.ts) stamps every variant's `price = listings.bundle_price`. This keeps the variant-level browse price filter (MEMORY 07-02) UNCHANGED: a set-only listing filters as a single-priced item at its set total (a $400 set is excluded by a max-$200 filter), while individual/either keep real per-size prices so the size+price coupling still holds (a $600 size-8 stays excluded by max-$400). No schema migration — `listing_sizes.price` stays NOT NULL. Chose this over (A) a denormalized `listings.min_price` column — rejected because it decouples size from price (would wrongly surface the $600 size-8 via a cheaper size in the same listing) — and over (B) a Postgres RPC/view — rejected as a heavy rewrite of the count/pagination/filter layer; both became unnecessary once set-only variants carry the set total. `bundle_price` stays on `listings` as the display source of truth (and the only home for `either`'s discount); the mirrored variant price is filter-only and never shown. Invariant "set_only ⇒ every variant.price == bundle_price" is app-enforced on create + update (variantRowsPayload runs on both; a CHECK can't reference another table and a trigger was avoided for simplicity), and read/delete need nothing extra (read is consistent by construction, delete cascades).

- [07-06-2026] decision: Multi-write listing mutations are atomic via Postgres RPCs (security invoker, `set search_path=''`, granted to authenticated), NOT client-side supabase-js sequences — because supabase-js talks to stateless PostgREST and can't hold a transaction across calls. `mark_listing_sold(p_listing_id)` (migration 010) flips listings.status + all listing_sizes.status in one tx (mirrors the old `.eq(user_id)` guard: `where user_id = auth.uid()` + row_count=0 → "Listing not found"). `update_listing_with_variants(p_listing_id, p_listing jsonb, p_variants jsonb)` (migration 011) updates the listing row + reconciles variants (delete removed / update price+sort_order preserving status / insert new via jsonb_to_recordset), replacing the TS `syncListingSizes` diff (now deleted, along with ExistingVariant type + the `sizes` embed in updateListing's existing-row select). sell.ts's updateListing now uploads images → calls the RPC → deletes ORPHAN images only AFTER the atomic commit (was before, which orphaned them on a mid-sync failure). Image upload/cleanup stay in the action (storage can't join a DB tx). Rejected an ORM (Drizzle/direct pg) that would allow TS-side transactions: conflicts with AGENTS "no ORM", loses RLS as the free ownership gate (direct conns bypass RLS), adds a 2nd data-access path + serverless pooling — disproportionate for two low-frequency partial-write windows. Verified with a BEGIN…ROLLBACK smoke test in the Supabase SQL editor (all checks PASS: variant diff, sold-variant status preserved, atomic rollback of listing row on a failed variant insert, mark-sold cascade, non-owner rejection). Cost: each behavior change to the variant-diff rules now means a new migration (`create or replace`) + schema.sql edit.

- [07-07-2026] decision: Browse listings grid is pure CSS — `grid-cols-[repeat(auto-fill,minmax(15rem,1fr))]` in ListingsGridWrap (now a tiny Server Component) replaced the ~100-line client-side ResizeObserver/rAF measuring version. `auto-fill` (not `auto-fit`) keeps empty tracks so sparse rows stay left-aligned in a full row; `1fr` max makes the column count derive from the 15rem min (dense packing, the old JS behavior) with tracks stretching to fill — accepted trade-off: no hard 18rem card cap (cards stretch ~1-2rem past it at 3+ cols, full-width at 1 col on phones). No hydration layout shift, no per-resize JS.

- [07-07-2026] decision: Desktop filter-rail toggle animates via the View Transitions API (`document.startViewTransition` + `flushSync` in ListingsLayout.toggleRail), NOT CSS `transition: grid-template-columns` — the old 700ms width transition re-laid-out the whole grid every frame (jank) and the auto-fill column-count change made a card jump rows un-animated mid-flight. Layout now snaps; the browser FLIP-animates snapshots: each GownCard Link carries `viewTransitionName: card-<id>` (cards glide between slots), the rail slides in from the left via `::view-transition-new/old(filter-rail):only-child` keyframes in globals.css (name applied only while open so open/close get entry/exit animations, not a width morph; exit is deliberately faster — 0.2s ease-in vs 0.35s springy entry — per exits-faster-than-entrances motion convention). Falls back to instant toggle when unsupported or prefers-reduced-motion. Gotchas learned: sticky chrome (navbar `site-nav`, subnav `browse-subnav`) needs its own view-transition-name + `z-index: 1` on the groups or gliding card snapshots fly OVER it when scrolled; and put the name ON the backdrop-blur element itself, never an ancestor wrapper — naming an ancestor isolates the subtree into its own snapshot layer and kills the frost.
